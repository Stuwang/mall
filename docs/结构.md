# 项目结构

仓库里是两个独立项目，加上两边都引用的 Go 模块。

```text
mall/
  admin/            商城管理后台（Vue 3 + Element Plus）
  web_app/          商城用户端 H5（Vue 3 + Vant）
  server/           商城 API
  im/               IM API 与 WebSocket
  im_web_app/       IM 用户端 H5（Vue 3 + Vant）
  modules/
    kit/            日志、错误、鉴权、HTTP 响应
    user/           用户账号、登录、管理接口
    file/           本地文件上传与访问
  build.go          生成 pb、编译 Go 目标
  go.work           本地同时使用上述 Go 模块
  scripts/          商城生产一体包（含前端构建）
  docs/
    mall/           商城文档
    im/             IM 文档
```

商城和 IM 不互相调用，不共享数据库、JWT 密钥和图片目录。各自进程自己初始化 `modules`。

商城服务内部见 [商城 / 结构](mall/结构.md)。IM 进程见 [设计](im/设计.md)。

## 模块依赖

```text
server  →  kit、user、file
im      →  kit、user、file
user    →  kit
file    →  kit

server 不依赖 im
im 不依赖 server
```

模块路径是 `mall/kit`、`mall/user`、`mall/file`。商城是 `helloworld`，IM 是 `mall/im`。`go.work` 把它们列在一起，本地编译不需要再写 `replace` 才能找到源码。`server/go.mod` 里仍保留 `replace`，方便不打开工作区时单独编译商城。

数据库由每个服务自己初始化。启动时把连接交给用户模块：

```text
database.InitDb(...)
userdao.SetDB(database.GetDb())
```

文件模块不读各服务的配置结构。调用方把存储配置填进 `mediastore.Config` 再调用 `mediastore.Init`。

## modules/kit

| 包 | 作用 |
|----|------|
| `logger` | 日志 |
| `codeerror` | 通用错误类型和错误码；`error.proto` 定义 `CodeError` |
| `auth` | JWT、白名单中间件 |
| `httpx` | 统一的 `{code,msg,data}` 响应 |
| `model/common` | 软删除标记 |
| `pbjson` | Kratos JSON codec |
| `hash_balancer` | 一致性哈希选节点 |

商城专用错误码在 `server/pkg/bizerror`。IM 专用错误码在 `im/pkg/bizerror`。

## modules/user

账号、登录方式、注册、登录、封禁和管理员接口。

```text
modules/user/
  model/            用户表、登录方式表
  dao/              数据访问；SetDB 注入连接
  controller/       注册、登录、资料、管理端
  api/user/         用户服务 proto
  api/base/         请求里的 BaseParam
```

## modules/file

```text
modules/file/
  mediastore/       本地图片存储、逻辑 URI 和公开 URL
  mediacontroller/  上传接口和 /files/ 访问
```
