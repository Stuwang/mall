# 范围

## 边界

IM 只做账号之间的一对一聊天。账号、成员行、消息都由 IM 进程写在自己的 `im.db`。

商城的商品、订单、购物车、积分、页面入口都不进入这个服务。IM 不调用商城接口，不打开商城的数据库，也不使用商城的 JWT 和图片目录。

可复用的是 `modules/kit`、`modules/user` 的代码。`modules/file` 一期不参与发送。user 模块的 `user`、`user_login` 表落在 `im.db`。

## 场景

两个用户互聊。用户发出的文本，双方都能看到。

另外有内部入口，由系统代替用户 A 给这场会话写一条文本，可见范围三选一：

| 情况 | A | B |
|------|---|---|
| 只给对方 | 看不到 | 看得到，发送者显示为 A |
| 只给发送者 | 看得到，出现在和 B 的会话里 | 看不到 |
| 双方都看 | 看得到 | 看得到 |

看不到的那一侧，会话列表和历史都不会出现这条，他自己的序号也不增加。还没发出任何可见消息时，服务端没有这一行，聊天页只留在本地。

## 一期做

| 能力 | 说明 |
|------|------|
| 账号 | 挂载 user 模块的注册、登录、资料、封禁 |
| 一对一 | 两个用户一场会话。`conv_id` 由两个用户 id 拼出。没有独立会话表，有可见消息才写成员行 |
| 文本 | 用户发送。1 到 2000 个 Unicode 码位 |
| 系统代发 | 上面三种可见性。只走内部接口，用户 token 不能指定可见性 |
| 预览开关 | 内部发送时，发送者一侧和对方一侧各一个开关，决定这次是否写入该侧列表上的最新消息 |
| 消息更新 | 看得到的每一侧把同步序号改成更大的新值。消息 id 和创建时间不变，客户端按消息 id 覆盖 |
| 历史 | 客户端保存本地记录，用自己的序号向后补。新设备从 0 拉到最新 |
| 会话列表 | 用这个用户跨会话的 `last_seq` 做增量，不做页码翻页 |
| 长连接 | 心跳，以及推送这个用户看得到的新消息和更新。推送是完整消息，先显示，再调接口同步 |
| HTTP 发送 | 发送只走 HTTP |
| 多端 | 一个用户最多 5 条连接。每条连接各自记游标，服务端把推送发到看得到这条的所有连接 |
| 幂等 | 用户发送带 `client_msg_id`，系统代发带 `request_id`。同键同正文返回同一条；同键不同正文拒绝 |

## 一期不做

- 已读、未读、已读游标
- 撤回、消息删除。以后删除保留原行并分配新序号，不做物理删除
- 离线消息信箱
- 在长连接上发送
- 只保留最近一页再向上翻
- 用区间向服务端补缺号
- 置顶、隐藏、清空本地记录
- 拉黑
- 图片、语音、视频、文件、业务卡片（`content_type` 只预留，不定义载荷）
- 群、聊天室
- 引用、表情回复
- 正在输入
- 系统级推送
- 全文搜索
- 管理端查看全部会话
- 多机和 Redis（[设计](设计.md) 里只留接法）
- 和商城互相调用
