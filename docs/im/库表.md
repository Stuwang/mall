# 库表

库文件是 IM 进程自己的 `im.db`。时间是 unix 秒，字段名 `ct` / `ut`。

消息不删除。本期没有撤回、拉黑、隐藏。以后若要删除，保留这一行，打上删除标记，并给看得到的一侧分配新的同步序号。物理删掉行之后，已经在本地的消息无法靠增量同步清掉。

`user`、`user_login` 由 user 模块建在同一个库里，结构以该模块为准。

聊天三张表。不建 `im_conversation`，不建回执表、设备表、拉黑表。

字段怎么一起变化，见 [字段](字段.md)。

## im_user_seq

一个用户一行。他所有会话的同步序号都从这里取。

| 列 | 类型 | 说明 |
|----|------|------|
| user_id | int64 PK | |
| seq | int64 | 已经分配过的最大同步序号。还没发过可见消息时没有这行，视作 0 |
| ut | int64 | |

下一次分配就是 `seq + 1`，写回这一行。只给看得到这次变更的用户分配。双方都看得见时，各更新各的行。

## im_conversation_member

每个用户在一场私聊里最多一行。没有可见消息时不存在。

| 列 | 类型 | 说明 |
|----|------|------|
| id | int64 PK | 自增。只标识这一行，不作为两边共用的会话 id |
| user_id | int64 | 这一行属于谁 |
| peer_user_id | int64 | 对方 |
| user_low | int64 | `min(user_id, peer_user_id)` |
| user_high | int64 | `max(user_id, peer_user_id)`。约束 `user_low < user_high` |
| conv_id | string | `{user_low}_{user_high}`，按整数比较后再格式化 |
| last_seq | int64 | 这一侧在这场会话里拿到过的最大同步序号 |
| last_msg_id | int64 | 这一侧列表上的最新消息。没有时为 0 |
| last_sender_id | int64 | 那条消息的名义发送者。没有时为 0 |
| last_preview | string | 那条文本的摘要，最多约 50 个码位 |
| sort_ut | int64 | 那条最新消息的 `ut`。列表展示按它倒序。没有时为 0 |
| ct / ut | int64 | |

唯一索引：`(user_id, peer_user_id)`。两边同时发出第一条时，冲突的插入视为行已存在，继续写消息。

同步：`user_id = ? AND last_seq > ?`，按 `last_seq` 升序。索引 `(user_id, last_seq)`。

展示：同一用户按 `sort_ut` 倒序，相同则按 `last_msg_id` 倒序。索引 `(user_id, sort_ut)`。

双方两行的 `conv_id`、`user_low`、`user_high` 相同。`last_seq`、最新消息和 `sort_ut` 可以不同。

## im_message

| 列 | 类型 | 说明 |
|----|------|------|
| id | int64 PK | 消息 id。同步不用它当游标。气泡顺序用它和 `ct` |
| user_low | int64 | 这场私聊 |
| user_high | int64 | |
| conv_id | string | 与成员行相同 |
| sender_id | int64 | 名义发送者。系统代发时也是被代替的那个用户 |
| origin | int32 | 1 用户自己发，2 系统代发 |
| visibility | int32 | 1 仅对方可见，2 仅发送者可见，3 双方可见。用户自己发恒为 3 |
| seq_low | int64 | `user_low` 这一侧的同步序号。看不见为 0。更新正文时改成更大的新值，旧值留空 |
| seq_high | int64 | `user_high` 这一侧的同步序号。规则同上 |
| idempotency_key | string | 用户发送是 `client_msg_id`，系统代发是 `request_id` |
| content_type | int32 | 1 文本。其他正整数保留，一期拒绝写入 |
| content | text | JSON。一期只有 `{"text":"..."}` |
| ct / ut | int64 | 创建写 `ct`。更新正文或同步序号时改 `ut` |

唯一索引：

- `(origin, sender_id, idempotency_key)`
- `(user_low, user_high, seq_low)`，仅 `seq_low > 0`
- `(user_low, user_high, seq_high)`，仅 `seq_high > 0`

后两个用部分唯一索引。看不见的消息把该侧序号存成 0，可以有多行。更新把序号改到新值后，旧值不再占用唯一索引。

某个用户拉自己的历史时：自己是 `user_low` 就用 `seq_low`，否则用 `seq_high`。条件是序号大于游标且序号大于 0，按该序号升序。

## 一次写入动哪些行

新建一条消息：

1. 可见的一侧保证成员行存在。不可见且还没有成员行的一侧不建。
2. 每个可见用户锁住自己的 `im_user_seq`，取出 `seq + 1`。双方都要取号时，按 `user_id` 从小到大加锁。
3. 把这个号写进 `seq_low` 或 `seq_high`。不可见侧写 0。
4. 可见侧的 `last_seq` 改成刚取到的号。
5. 这一侧的预览开关为真，并且这条按创建顺序新于该侧当前最新消息时，才更新 `last_msg_id`、`last_sender_id`、`last_preview`、`sort_ut`。创建顺序先看 `ct`，相同再看 `msg_id`。还没有最新消息时，这条就是最新。`sort_ut` 用这条消息的 `ut`。用户发送两侧都为真。

更新一条已有消息：

1. 改正文，`ut` 改为现在。`msg_id`、`ct` 不动。
2. 每个仍能看见这条的用户再取一个新序号，写回他那一列。另一侧保持 0。
3. 这些用户的 `last_seq` 改成各自的新序号。
4. 预览开关为真，且 `msg_id` 等于该侧当前的 `last_msg_id` 时，用新正文重写预览，并把 `sort_ut` 改成新的 `ut`。否则最新消息和排序时间保持原样。

幂等命中且正文与第一次相同：上面的更新都不做，返回原行。幂等键相同但正文不同：整次拒绝。

锁顺序：先按 `user_id` 从小到大锁 `im_user_seq`，再按同样顺序锁成员行。
