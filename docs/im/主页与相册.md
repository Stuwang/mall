# 主页与相册

每人一个相册，就是按时间排列的照片列表。登录用户可以打开任何人的主页，并看他的相册。不建相册夹，照片不设可见范围。

帖子见 [帖子](帖子.md)。主页不展示帖子。

## 和现有能力的关系

资料仍在 user 模块的 `user` 表：`id`、`nickname`、`sex`、`avatar`、`ban_until`。头像继续用「我的」里已有的修改资料和 `POST /user/api/v1/media/upload`。

`POST /user/api/v1/info` 按 id 能查到别人，但响应里有登录账号、是否管理员、封禁时间。主页不走这个接口。

图片先上传，再把逻辑 URI 写入相册。校验和聊天图片相同：必须是本进程 `mediastore` 里已有的 `local_file` 文件。出站把 URI 转成 `/files/...`。文件本体不随软删除清掉。

库仍是 IM 进程的 `im.db`。不访问商城库。

## 本期做

| 能力 | 说明 |
|------|------|
| 主页 | 头像、昵称、用户 id、相册张数。自己和别人同一页 |
| 相册 | 添加、删除自己的照片；按 id 从新到旧翻页 |
| 说明 | 添加时可选一句说明，之后不改 |
| 入口 | 「我的」进自己的主页；在线列表点头像、聊天页点对方、帖子里点作者，进对方主页 |
| 发消息 | 主页上的按钮进入现有私聊，不新做会话 |

## 本期不做

- 多个相册、拖拽排序、封面、编辑说明
- 仅自己可见、好友可见。没有好友关系
- 对照片点赞、评论
- 视频
- 把相册照片发进帖子或聊天
- 管理端审核相册
- 删除后回收磁盘文件
- 主页上列这个人的帖子

## 谁能看

读接口都要登录。

| 对象 | 自己 | 别人 |
|------|------|------|
| 未封禁 | 可看、可改自己的相册 | 可看主页和相册，不能改 |
| 已封禁 | 仍可看自己的主页和相册；添加和删除返回 1014 | 主页和相册都返回 1014 |
| 不存在 | — | 1007 |

封禁判断用 `user.Banned()`，和 WebSocket 升级时一致。HTTP 中间件目前不拦封禁，这两个写接口要自己查。

主页不返回登录账号、管理员标记、封禁截止时间、密码。`sex` 库里没有枚举，主页不返回、不展示。

别人的照片 id 拿去删除，当作这张照片不存在，返回 1120。不返回 1009，避免靠错误码探出照片属于谁。

## 功能

### 主页

展示头像、昵称、用户 id、相册张数。张数是未删除照片的条数，读取时现算，不冗余一列。

别人的主页显示「发消息」，进入 `/chat/:peerId`。对方还没有会话时，沿用现在的本地会话，第一条消息发出后才有成员行。添加和删除照片在相册详情里，只对自己的相册出现。

在线列表点头像进入主页，点「消息」进入聊天。聊天页点标题里的对方进入主页。

### 相册

一张照片一行。列表按 `id` 降序，新的在前。

添加：

1. 客户端先 `POST /user/api/v1/media/upload`，表单字段 `file`。类型和大小沿用 `mediastore`：jpeg、png、gif、webp，默认最大 5MB。
2. 再把返回的 `uri` 交给添加接口。`/files/` 路径也可以，服务端归一化成逻辑 URI，并确认文件能打开。打不开返回 1000。
3. 未删除张数已经达到 100 时返回 1121，不插入。
4. 说明可空。去掉首尾空白后，0 到 80 个 Unicode 码位。超长返回 1000。

同一文件添加两次会得到两行。上传本身每次都是新文件，不按 URI 做唯一约束，也不做复活。

删除只软删除。已删除或不属于自己，返回 1120。再次删除同一张仍是 1120。

## 库表

表 `im_album_photo`。时间是 unix 秒。`deleted` 使用 `mall/kit/model/common.DeletedFlag`：0 未删除，1 已删除。这个字段不出现在接口里。

| 列 | 类型 | 说明 |
|----|------|------|
| id | int64 PK | 自增。翻页游标 |
| user_id | int64 | 照片属于谁 |
| uri | string | 逻辑 URI，如 `local_file:///2026/10/27/xxx.jpg` |
| caption | string | 说明，可空 |
| deleted | int32 | 0 未删除，1 已删除 |
| ct / ut | int64 | 添加时两者相同。删除时改 `ut` 和 `deleted` |

索引 `(user_id, deleted, id)`。列表条件是 `user_id = ? AND deleted = 0 AND id < ?`，按 `id` 降序。

不建 `im_album`。用户没有照片时，主页张数为 0，列表为空。

## 接口

挂在 IM 进程，`POST`、JSON、响应 `{code, msg, data}`。前缀 `/im/api/v1/`。用户 id 从鉴权取，不读 `BaseParam`。

Proto 放在 `im/api/profile/profile.proto`，服务名 `Profile`。不在 `common.proto` 增加枚举：删除标记不进接口，照片也没有状态枚举。

生成仍用仓库根目录的 `go run build.go proto`。`im/internal/app` 里 `RegisterProfileHTTPServer`。

### 主页

`POST /im/api/v1/profile/get`

```json
{ "user_id": 2 }
```

`user_id <= 0` 表示自己。

```json
{
  "user_id": 2,
  "nickname": "小王",
  "avatar": "/files/2026/10/27/a.jpg",
  "photo_count": 3
}
```

`avatar` 是可访问路径。没设头像时为空字符串。`photo_count` 只计未删除。

### 相册列表

`POST /im/api/v1/album/list`

```json
{ "user_id": 2, "before_id": 0, "limit": 30 }
```

| 字段 | 说明 |
|------|------|
| user_id | `<= 0` 表示自己。可见性和主页相同，封禁、不存在先按主页返回 |
| before_id | 0 表示从最新一张开始。正数时返回更小的 id |
| limit | 0 时默认 30，最大 50 |

```json
{
  "list": [
    {
      "id": 9,
      "image_url": "/files/2026/10/27/b.jpg",
      "caption": "",
      "ct": 1761500000
    }
  ],
  "has_more": false
}
```

本页满了则 `has_more = true`，下一页的 `before_id` 用本页最后一条的 `id`。没有照片时 `list` 为空，`has_more = false`。

### 添加

`POST /im/api/v1/album/add`

```json
{
  "image_uri": "local_file:///2026/10/27/b.jpg",
  "caption": "周末"
}
```

只写自己的相册。成功返回刚写入的照片对象，字段和列表元素相同。不返回逻辑 URI。

### 删除

`POST /im/api/v1/album/delete`

```json
{ "photo_id": 9 }
```

成功时 `data` 为空对象。行保留，`deleted = 1`。

## 错误码

通用码沿用 kit：参数 1000、未登录 1005、用户不存在 1007、封禁 1014、系统 1。

| code | 何时 |
|------|------|
| 1120 | 照片不存在、已删除，或不是自己的照片 |
| 1121 | 未删除照片已有 100 张 |

1000 用于：说明超长，`image_uri` 为空、不是本进程文件、文件打不开。业务错误打日志后原样返回，不把底层错误文案给客户端。

## 客户端

`im_web_app`：

| 路由 | 说明 |
|------|------|
| `/u/:userId` | 主页，不是底栏 tab。`:userId` 是对方或自己 |
| `/u/:userId/album` | 相册详情，照片按列表展示 |

- 「我的」增加「主页」，打开自己的 `/u/:id`。昵称、头像、退出仍留在「我的」。
- 在线列表：点头像进主页，点「消息」开聊。整行其余区域不跳转。
- 聊天页标题进对方主页。
- 主页展示头像、昵称、用户 id、相册张数。相册是左右滑动的预览，点预览进入相册详情。
- 相册详情是列表。点一张照片走现有 `ImageViewer`。自己的照片可删除，可添加。空相册文案：还没有照片。
- 添加中、删除失败要有提示。上传失败不调用添加接口。

底栏不变，仍是三个 tab。帖子 tab 在 [帖子](帖子.md) 里加，加上之后主页路由保持不是 tab。

## 代码落点

| 位置 | 内容 |
|------|------|
| `im/pkg/model` | `AlbumPhoto` |
| `im/pkg/dao/album_photo_dao.go` | 单表 Dao。`NewAlbumPhotoDao(nil)` 用全局库，`NewAlbumPhotoDao(tx)` 用事务 |
| `im/pkg/biz` | 张数上限、URI 归一化（复用现有 `normalizeImageURI`）、封禁判断 |
| `im/pkg/bizerror` | 1120、1121 |
| `im/pkg/controller` | HTTP。参数错误和下游错误都打日志 |

添加和删除各是一次单表写，不必跨表事务。列表和主页的张数是两次读，张数允许和紧接着的列表差一张。
