# 范围

## 边界

IM 只做账号之间的一对一聊天。账号、成员行、消息都由 IM 进程写在自己的 `im.db`。

商城的商品、订单、购物车、积分、页面入口都不进入这个服务。IM 不调用商城接口，不打开商城的数据库，也不使用商城的 JWT 和图片目录。

可复用的是 `modules/kit`、`modules/user` 的代码。`modules/file` 一期不参与发送。user 模块的 `user`、`user_login` 表落在 `im.db`。

## 场景

两个用户互聊。用户发出的文本，双方都能看到。

另外有内部入口，由系统代替用户 A 给这场会话写一条文本，可见范围三选一：

| 情况 | A | B |
|------|---|---|
| 只给对方 | 看不到 | 看得到，发送者显示为 A |
| 只给发送者 | 看得到，出现在和 B 的会话里 | 看不到 |
| 双方都看 | 看得到 | 看得到 |

看不到的那一侧，会话列表和历史都不会出现这条，他自己的序号也不增加。

## 一期做

| 能力 | 说明 |
|------|------|
| 账号 | 挂载 user 模块的注册、登录、资料、封禁 |
| 一对一 | 两个用户一场会话。会话没有独立的表，双方各一行成员记录 |
| 文本 | 用户发送。1 到 2000 个 Unicode 码位 |
| 系统代发 | 上面三种可见性。只走内部接口，用户 token 不能指定可见性 |
| 预览开关 | 内部发送时，发送者一侧和对方一侧各一个开关，决定是否改写该侧会话列表预览 |
| 消息更新 | 更新后把该行的同步序号 `seq` 改成新值，便于客户端增量同步。视图序号不变 |
| 历史 | 按这个用户自己的序号向前翻、向后补 |
| 长连接 | 只推这个用户看得到的新消息 |
| HTTP 发送 | 长连接断开时仍能发，和长连接共用一套写入 |
| 多端 | 一个用户最多 5 条连接。每条连接各自做同步，服务端只负责都推到 |
| 幂等 | 用户发送带 `client_msg_id`，系统代发带 `request_id`。重复请求返回同一条 |

## 一期不做

- 已读、未读、已读游标
- 撤回
- 置顶、隐藏、清空本地记录
- 拉黑
- 图片、语音、视频、文件、业务卡片（`content_type` 只预留，不定义载荷）
- 群、聊天室
- 引用、表情回复
- 正在输入
- 系统级推送
- 全文搜索
- 管理端查看全部会话
- 多机和 Redis（[设计](设计.md) 里只留接法）
- 和商城互相调用
