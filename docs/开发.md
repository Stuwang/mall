# 开发

## 依赖

- Go 1.23 及以上（当前工作区声明为 1.24.1）
- Node.js（只在改 `admin` 或 `web_app` 时需要）
- `protoc`，以及插件 `protoc-gen-go`、`protoc-gen-go-grpc`、`protoc-gen-go-http`、`protoc-gen-openapi`

在仓库根目录执行 Go 命令，这样会用到 `go.work`。

## 启动商城 API

```bash
cd server
go run ./cmd -conf configs/config.yaml
```

默认监听 `:8080`。`configs/config.yaml` 里 `env: test` 时，鉴权读请求头 `UserId`，不校验 JWT。和前端联调时把 `env` 改成非 `test`，登录接口才会发 JWT。

管理端：

```bash
cd admin
npm install
npm run dev
```

开发服务器把接口代理到 `http://localhost:8080`。

用户端 H5 默认端口 `5174`，同样代理到 API：

```bash
cd web_app
npm install
npm run dev
```

## 生成 pb

只改 proto，不要手改 `*.pb.go`、`*_http.pb.go`、`*_grpc.pb.go` 和 `server/openapi.yaml`。

```bash
go run build.go proto
```

这条命令会生成：

| 源文件 | 产物 |
|--------|------|
| `server/api/**/*.proto`（路径中含 `errors` 的除外） | Go、HTTP、gRPC |
| `modules/user/api/user/user.proto` 及其引用的 `base.proto` | Go、HTTP、gRPC |
| `im/api/im/im.proto` | Go、HTTP、gRPC |
| `modules/kit/**/*.proto` | 只有 `.pb.go`（这些文件没有 HTTP/gRPC service） |
| 上述商城接口和用户接口 | `server/openapi.yaml` |

## 编译

仍在仓库根目录：

```bash
go run build.go build server      # bin/server（Windows 为 bin/server.exe）
go run build.go build allinone    # bin/allinone
go run build.go build kit         # 也可写 user、file
go run build.go build all         # 三个模块加上两个可执行文件
```

`build allinone` 只编译 Go，并嵌入 `server/cmd/allinone/static` 里已经放好的前端文件。要先构建前端再打进二进制，用 [部署](部署.md) 里的脚本。
