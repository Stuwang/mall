# 帖子

登录用户可以发帖、评论、点赞。帖子带点赞数和评论数。底栏第二个 tab 是「帖子」，打开就是推荐列表。

推荐不是一种用户操作，也没有单独的推荐数。它是列表排序：`recommend_score = like_count + comment_count`，分数高的在前；分数相同，`id` 大的在前。因此还没有任何互动时，推荐列表就是从新到旧。

主页和相册见 [主页与相册](主页与相册.md)。帖子正文只有文字，图片放进相册，不进帖子。

## 和现有能力的关系

作者的头像、昵称读 `user` 表，出站头像仍转成 `/files/...`。不新建用户资料表。

帖子、评论、点赞写在 IM 自己的 `im.db`。不走 WebSocket，不占 `im_user_seq`。打开 tab 或下拉时重新拉第一页。

身份从鉴权取。写接口要自己查 `user.Banned()`：当前 HTTP 中间件不拦封禁，只有 WebSocket 升级会拦。

没有好友和关注。推荐列表对所有未封禁作者的未删除帖子可见。

## 本期做

| 能力 | 说明 |
|------|------|
| 发帖 | 1 到 1000 个 Unicode 码位。带 `client_post_id` 幂等 |
| 删帖 | 只删自己的，软删除。列表和详情不再出现 |
| 评论 | 一条帖子下的平级评论，1 到 300 个码位。不楼中楼 |
| 删评论 | 只删自己的评论，软删除，评论数和推荐分减一 |
| 点赞 | 一人一帖一次。再次点赞不增加计数。取消点赞减一。取消后再点赞复活原行 |
| 计数 | 帖子行上的 `like_count`、`comment_count`，和列表、详情一起返回 |
| 推荐 | 底栏第二个 tab 的唯一列表，按上面的分数排序 |
| 是否已赞 | 列表和详情带当前用户的 `liked` |

## 本期不做

- 帖子图片、视频、话题、@、转发、置顶、搜索
- 评论的点赞和回复
- 关注、好友可见、仅自己可见
- 运营推荐、权重配置、时间衰减
- 新帖或新评论的长连接推送
- 管理端审核、举报
- 在主页列出这个人的帖子
- 未读红点。帖子 tab 不显示角标

## 谁能看、谁能写

| 动作 | 规则 |
|------|------|
| 看推荐、详情、评论 | 登录即可。帖子已删除返回 1130。作者当前封禁时，推荐里不出现；点进详情也返回 1130 |
| 发帖、评论、点赞、取消点赞 | 自己处于封禁返回 1014 |
| 删帖 | 只能删自己的。别人的、已删除的，返回 1130 |
| 删评论 | 只能删自己的。别人的、已删除的、帖子已删除的，返回 1131。帖子已删除时优先返回 1130 |

可以给自己的帖子点赞和评论。

作者被封禁后，他的旧帖不从库里删，只是推荐和详情不再给出。解封后重新出现，计数仍是封禁前的值。

## 功能

### 底栏

现在是「在线」「消息」「我的」。改为：

| 顺序 | tab | 路由 |
|------|-----|------|
| 1 | 在线 | `/` |
| 2 | 帖子 | `/posts` |
| 3 | 消息 | `/convs` |
| 4 | 我的 | `/mine` |

「消息」仍用现有未读角标。帖子详情 `/posts/:postId` 不占底栏。

### 推荐列表

一页默认 20 条，最多 50。卡片展示：作者头像和昵称、正文、点赞数、评论数、是否已赞、创建时间。正文超过约四行在列表里截断，详情展示全文。

点卡片进详情。点头像或昵称进 [主页](主页与相册.md) 的 `/u/:userId`。

下拉刷新丢掉游标，重新要第一页。点赞或评论之后，这一条的计数以该操作的响应为准；排序要等下次刷新才变。翻页过程中别人点赞，可能使相邻两页重复或漏掉一条，客户端不补洞。

空列表文案：还没有帖子。

### 发帖

帖子 tab 右上角「发布」。提交成功后回到列表并刷新第一页。

`client_post_id` 由客户端生成，8 到 64 位，字符集 `[A-Za-z0-9_-]`，和聊天的 `client_msg_id` 相同。同一用户：

| 情况 | 结果 |
|------|------|
| 第一次 | 落库 |
| 同键且正文相同 | 返回原帖，不插第二行，计数不变 |
| 同键但正文不同 | 1133，不改已有行 |

用户改了字再发，换新的 `client_post_id`。

### 点赞

详情和列表都可以点。已赞再点一次视为成功，计数不变。未赞时取消点赞同样视为成功，计数不变。

取消后再赞，把原来的点赞行从软删除恢复，不新插一行。`(post_id, user_id)` 唯一。

点赞数不会变成负数。减计数时带 `like_count > 0`。

### 评论

详情里按 `id` 升序，旧的在上。默认 30 条，最多 50。用 `after_id` 继续向后要。

`client_comment_id` 的字符规则和帖子相同。幂等范围是同一用户的同一条帖子：同键同正文返回原评论，同键不同正文返回 1133。

删除自己的评论后，评论数和推荐分减一，点赞数不动。减评论数时带 `comment_count > 0`。

## 库表

三张表。时间是 unix 秒。`deleted` 使用 `mall/kit/model/common.DeletedFlag`，不出现在接口里。计数和推荐分只由服务端在事务里改，不接受客户端传入。

### im_post

| 列 | 类型 | 说明 |
|----|------|------|
| id | int64 PK | 自增 |
| user_id | int64 | 作者 |
| client_post_id | string | 幂等键 |
| text | text | 正文 |
| like_count | int64 | 未删除的点赞数，起始 0 |
| comment_count | int64 | 未删除的评论数，起始 0 |
| recommend_score | int64 | `like_count + comment_count` |
| deleted | int32 | 0 未删除，1 已删除 |
| ct / ut | int64 | 发帖时两者相同。计数变化或删除时改 `ut`。`ct` 不变 |

唯一索引 `(user_id, client_post_id)`。

推荐列表索引 `(deleted, recommend_score, id)`。查询 `deleted = 0`，按 `recommend_score DESC, id DESC`。作者是否封禁在查出用户后过滤；一页因此可能短于 `limit`。短页不表示没有下一页，以 `has_more` 为准。`has_more` 表示按分数往下还有未删除帖子，不管那些作者是不是封禁。

### im_post_comment

| 列 | 类型 | 说明 |
|----|------|------|
| id | int64 PK | |
| post_id | int64 | |
| user_id | int64 | 评论者 |
| client_comment_id | string | 幂等键 |
| text | text | |
| deleted | int32 | |
| ct / ut | int64 | 删除时改 `ut` |

唯一索引 `(post_id, user_id, client_comment_id)`。

列表索引 `(post_id, deleted, id)`。条件 `post_id = ? AND deleted = 0 AND id > ?`，按 `id` 升序。

### im_post_like

| 列 | 类型 | 说明 |
|----|------|------|
| id | int64 PK | |
| post_id | int64 | |
| user_id | int64 | |
| deleted | int32 | 取消点赞置 1，再次点赞置回 0 |
| ct / ut | int64 | 第一次插入写 `ct`。复活或取消时改 `ut`，`ct` 保留 |

唯一索引 `(post_id, user_id)`。软删除后再次点赞更新这一行，不插入第二行。

### 一次写入动哪些行

发帖：插 `im_post`，三个计数都是 0。不写点赞行和评论行。

点赞或取消，在一个事务里：

1. 锁帖子行。已删除或作者封禁则整次回滚，对外 1130 或按封禁返回 1014（作者封禁与帖子删除对外都是 1130；操作者自己封禁在事务前返回 1014）。
2. 按 `(post_id, user_id)` 取点赞行。
3. 未赞到已赞：没有行就插入；有行且已删除则把 `deleted` 改回 0。然后 `like_count + 1`，`recommend_score = like_count + comment_count`（用更新后的点赞数）。
4. 已赞到未赞：行存在且未删除时，`deleted = 1`，`like_count - 1`（仅当 `like_count > 0`），重算推荐分。
5. 状态和请求一致：不改计数，提交并返回当前帖子。

评论新增：同一事务里插评论行，`comment_count + 1`，重算推荐分。删评论：软删除评论行，`comment_count - 1`，重算推荐分。帖子行都要先锁。

删帖：只把帖子 `deleted` 置 1。点赞行、评论行和计数留着。恢复帖子本期没有接口。

锁只锁这一条帖子。不同帖子互不影响。SQLite 写事务本身串行，仍然按「先帖子、再点赞或评论」写，避免以后换库时顺序不一致。

## 接口

`POST`、JSON、`{code, msg, data}`。前缀 `/im/api/v1/`。Proto 放在 `im/api/post/post.proto`，服务名 `Post`。枚举不新增：没有帖子状态进接口，删除标记也不进接口。

`go run build.go proto` 之后，在 `im/internal/app` 注册 `RegisterPostHTTPServer`。

帖子对象：

```json
{
  "post_id": 12,
  "user_id": 2,
  "nickname": "小王",
  "avatar": "/files/2026/10/27/a.jpg",
  "text": "今天天气不错",
  "like_count": 3,
  "comment_count": 1,
  "liked": true,
  "ct": 1761500000
}
```

`liked` 只对当前登录用户。作者没有昵称时返回空字符串，客户端用 `用户` 加 id 展示，和在线列表一致。

评论对象：

```json
{
  "comment_id": 4,
  "post_id": 12,
  "user_id": 1,
  "nickname": "小李",
  "avatar": "",
  "text": "确实",
  "ct": 1761500100
}
```

### 推荐

`POST /im/api/v1/post/recommend`

```json
{
  "has_cursor": false,
  "cursor_score": 0,
  "cursor_id": 0,
  "limit": 20
}
```

第一页 `has_cursor = false`，忽略两个 cursor。下一页把 `has_cursor` 设为 true，cursor 用上一页最后一条的 `recommend_score` 和 `post_id`。

条件是分数更小，或分数相同且 `post_id` 更小。不能只用 `cursor_score = 0` 表示第一页，因为没有互动的帖子分数就是 0。

```json
{
  "list": [],
  "has_more": false
}
```

`limit` 为 0 时默认 20，最大 50。

### 发帖

`POST /im/api/v1/post/create`

```json
{
  "client_post_id": "p-8f3a0001",
  "text": "今天天气不错"
}
```

成功返回帖子对象。正文去掉首尾空白后计数。空或超过 1000 个码位返回 1000。`client_post_id` 不合法返回 1000。

### 删除帖子

`POST /im/api/v1/post/delete`

```json
{ "post_id": 12 }
```

成功时 `data` 为空对象。

### 详情

`POST /im/api/v1/post/detail`

```json
{ "post_id": 12 }
```

成功返回帖子对象。不含评论，评论走列表接口。

### 点赞与取消

`POST /im/api/v1/post/like`

`POST /im/api/v1/post/unlike`

```json
{ "post_id": 12 }
```

成功都返回点赞之后的帖子对象，客户端用它覆盖本地的计数和 `liked`。

### 评论列表

`POST /im/api/v1/post/comment/list`

```json
{ "post_id": 12, "after_id": 0, "limit": 30 }
```

`after_id = 0` 从最早一条未删除评论开始。返回 `id` 更大的评论，升序。`limit` 为 0 时默认 30，最大 50。

```json
{
  "list": [],
  "has_more": false
}
```

帖子不可见时返回 1130，不返回空列表。`has_more` 为真时，下一页 `after_id` 用本页最后一条的 `comment_id`。

### 发表评论

`POST /im/api/v1/post/comment/create`

```json
{
  "post_id": 12,
  "client_comment_id": "c-8f3a0001",
  "text": "确实"
}
```

```json
{
  "comment": {},
  "post": {}
}
```

`post` 是计数已更新的帖子对象。正文规则同发帖，上限 300 个码位。

### 删除评论

`POST /im/api/v1/post/comment/delete`

```json
{ "comment_id": 4 }
```

成功返回更新后的帖子对象，不含被删评论。

## 错误码

| code | 何时 |
|------|------|
| 1000 | 正文为空或超长；`client_post_id`、`client_comment_id` 不合法；id 不是正数 |
| 1014 | 操作者自己处于封禁，发生在发帖、评论、点赞、取消点赞、删帖、删评论 |
| 1130 | 帖子不存在、已删除、作者当前封禁，或删的不是自己的帖子 |
| 1131 | 评论不存在、已删除，或删的不是自己的评论 |
| 1133 | 同一个幂等键提交了不同正文 |

1007 只用于主页那类「用户 id 本身不存在」。帖子接口里作者不存在按帖子不可见处理，返回 1130。

## 客户端

`im_web_app` 的 `TabLayout`：`tabRoutes` 在在线和消息之间插入帖子。

| 页面 | 行为 |
|------|------|
| `/posts` | 推荐列表，下拉刷新，滚到底用 cursor 要下一页 |
| 发布 | 从帖子 tab 进入。失败留在编辑页，保留正文 |
| `/posts/:postId` | 全文、点赞、评论列表、底部输入框 |
| 点作者 | ` /u/:userId` |

点赞可以先改本地图标，请求失败再改回，并以响应里的 `like_count`、`liked` 为准。不要用本地加减代替响应计数。

评论发送失败保留输入。删除评论只出现在自己的评论上。

## 代码落点

| 位置 | 内容 |
|------|------|
| `im/pkg/model` | `Post`、`PostComment`、`PostLike` |
| `im/pkg/dao/post_dao.go` | 只操作 `im_post` |
| `im/pkg/dao/post_comment_dao.go` | 只操作评论表 |
| `im/pkg/dao/post_like_dao.go` | 只操作点赞表。已删除行用更新复活 |
| `im/pkg/biz` | 开事务，把同一个 `tx` 注入上述 Dao。推荐分在帖子更新语句里写成两列之和 |
| `im/pkg/bizerror` | 1130、1131、1133 |
| `im/pkg/controller` | HTTP。每条错误路径打日志 |

一表一个 Dao。跨表的点赞、评论、删评论放在 biz 的事务里，不在某一个 Dao 里写另一张表。
