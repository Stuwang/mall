# 部署

开发时分别启动 `server`、`admin`、`web_app`。生产用 `cmd/allinone` 把 API 和两个前端静态站打进一个进程。

## 端口

| 服务 | 默认地址 | 说明 |
|------|----------|------|
| API | `:8080` | 配置项 `server.http_addr` |
| Admin | `:8081` | `-admin-addr` 可改 |
| H5 | `:8082` | `-web-addr` 可改 |

Admin 和 H5 会把各自的 API 路径反代到 API 端口。前端继续使用相对路径。

## 构建一体包

脚本会安装依赖、构建两个前端、把 `dist` 拷进 `server/cmd/allinone/static`，再编译 Go。

```bash
# 当前平台
sh scripts/build_prod.sh

# 交叉编译 Linux（默认 amd64；第二个参数可选 arm64）
sh scripts/build_prod.sh linux
sh scripts/build_prod.sh linux arm64
```

```powershell
.\scripts\build_prod.ps1
.\scripts\build_prod.ps1 -Target linux
.\scripts\build_prod.ps1 -Target linux -Arch arm64
```

产物是 `bin/mall-<os>-<arch>`（Windows 带 `.exe`）。当前平台还会复制一份 `bin/mall` 或 `bin/mall.exe`。编译时 `CGO_ENABLED=0`，SQLite 使用纯 Go 驱动，可以在 Windows 或 macOS 上直接编出 Linux 二进制。

只编译已经准备好静态文件的一体包时，用 `go run build.go build allinone`。它不会重新构建前端。

## 运行

在 `server/` 下启动，这样配置、数据库和 `data/images` 的相对路径才对：

```bash
cd server
../bin/mall -conf configs/config_prod.yaml
```

可选参数：`-admin-addr :8081`、`-web-addr :8082`。

上线前把 `configs/config_prod.yaml` 里的 `storage.public_base` 改成对外可访问的 API 地址，否则图片 URL 会指向错误的主机。`env` 不要用 `test`，并设置 `auth.jwt_secret`。
