# 接口

聊天接口由 IM 进程提供：`POST`、JSON、响应 `{code, msg, data}`，包装用 `modules/kit` 的 httpx。用户接口前缀 `/im/api/v1/`。用户 id 从鉴权取。

注册、登录、资料、封禁挂 user 模块已有的 HTTP，不在这里列。

非 test 环境用户接口带 `Authorization: Bearer <jwt>`，密钥是 IM 自己的。test 环境带 Header `UserId`。WebSocket 的凭据见下文。

成功时 `code = 0`。业务失败同样 HTTP 200，靠 `code` 区分。

同步怎么用这些接口，见 [同步](同步.md)。序号的含义见 [字段](字段.md)。

## 用户 HTTP

自己的用户 id 不传。`BaseParam` 若为了和 user 模块的 proto 生成链对齐可以留着，服务端不从里面取身份。

### 会话

`POST /im/api/v1/conv/open`

```json
{ "peer_user_id": 2 }
```

保证双方成员行存在。已存在则直接返回自己的那一行。`peer_user_id` 必须是本服务的用户，且不能是自己。

`POST /im/api/v1/conv/list`

```json
{ "page": 1, "page_size": 20 }
```

`page_size` 最大 50。按自己的 `last_msg_at` 倒序。

```json
{
  "list": [],
  "total": 1
}
```

列表元素是下方的会话对象。

### 消息

`POST /im/api/v1/msg/history`

```json
{
  "peer_user_id": 2,
  "cursor_seq": 0,
  "direction": 2,
  "limit": 50
}
```

| 字段 | 说明 |
|------|------|
| direction | 1 向更早。`cursor_seq = 0` 表示从自己的最新一条往前 |
| direction | 2 向更新。返回自己的 `seq > cursor_seq`，升序。同步只用这个方向 |
| limit | 默认 20，最大 50 |

`data.list` 在两个方向都按自己的 `seq` 升序。另外返回：

```json
{ "list": [], "last_seq": 10, "has_more": false }
```

`last_seq` 是这个用户成员行上的当前值。`direction = 2` 时，`has_more` 表示本页最大序号仍小于 `last_seq`。看不见的消息不会出现。

`POST /im/api/v1/msg/send`

```json
{
  "peer_user_id": 2,
  "client_msg_id": "c-8f3a",
  "content_type": 1,
  "text": "你好"
}
```

双方都可见。`content_type` 一期只能是 1。重复的 `client_msg_id` 返回已存在的那条，`code` 仍为 0。返回值是下面的消息对象，其中 `seq` 是**发送者自己的**序号。

成员行不存在时，发送会先把双方建出来，再写入。

## 内部代发

`POST /im/internal/v1/msg/send`

不接受用户 JWT。Header `X-Im-System-Token` 与配置 `im.system_token` 一致。用户长连接里没有这条命令。

```json
{
  "sender_id": 1,
  "peer_user_id": 2,
  "visibility": 1,
  "sender_preview": false,
  "peer_preview": true,
  "request_id": "sys-1001",
  "content_type": 1,
  "text": "只给对方看的文本"
}
```

| 字段 | 含义 |
|------|------|
| visibility = 1 | 仅 `peer_user_id` 可见 |
| visibility = 2 | 仅 `sender_id` 可见 |
| visibility = 3 | 双方可见 |
| sender_preview | 是否更新名义发送者的会话列表预览 |
| peer_preview | 是否更新对端的会话列表预览 |

不可见的一侧不能把对应预览开关设为 true。

`POST /im/internal/v1/msg/update` 更新已有消息的正文，并把该行 `seq` 改成新的同步序号。`view_seq` 不变。请求里同样带 `sender_preview`、`peer_preview`，决定这次更新要不要重写某一侧的预览。

`sender_id` 与 `peer_user_id` 都不能缺，且不能相同，都必须是本服务用户。重复的 `request_id`（在该 `sender_id` 下）返回第一次的结果。

```json
{
  "msg_id": 2,
  "seq": 5,
  "sender_view_seq": 0,
  "peer_view_seq": 2
}
```

看不见的一侧视图序号为 0。`seq` 是这场私聊的同步序号。用户接口只返回当前用户自己的 `view_seq`。

## 对象

会话，是当前用户自己的成员行：

```json
{
  "peer": { "user_id": 2, "nickname": "小王" },
  "last_seq": 2,
  "last_sync_seq": 4,
  "last_msg": {
    "msg_id": 3,
    "view_seq": 2,
    "sender_id": 1,
    "origin": 2,
    "content_type": 1,
    "preview": "只在我这边的文本",
    "ct": 1761321600
  },
  "last_msg_at": 1761321600
}
```

还没有自己可见的消息时，`last_seq = 0`，`last_msg` 为空对象。

消息：

```json
{
  "msg_id": 3,
  "seq": 4,
  "view_seq": 2,
  "sender_id": 1,
  "origin": 2,
  "client_msg_id": "",
  "content_type": 1,
  "content": { "text": "只在我这边的文本" },
  "ct": 1761321600
}
```

`view_seq` 是当前用户的视图序号，创建后不变。`seq` 是同步序号，消息被更新后会变成更大的新值。`origin` 为 1 时是用户所发，为 2 时是系统代发。用户所发的消息带上发送者的 `client_msg_id`，供其他端和 ack 去重。系统消息这一字段为空。

`content_type` 以外的取值一期不会出现在响应里。列仍然留在表上，供以后的类型使用。

## WebSocket

`GET /im/ws?access_token=<jwt>`

test 环境：`GET /im/ws?user_id=1`

帧是文本 JSON，上限 64KB。

客户端发给服务端：

```json
{ "cmd": "msg.send", "req_id": "1", "data": {} }
```

`data` 与 HTTP 发送体相同。

应答：

```json
{ "cmd": "msg.send.ack", "req_id": "1", "code": 0, "msg": "success", "data": {} }
```

`data` 是消息对象。服务端主动推送没有 `req_id`：

```json
{ "cmd": "msg.push", "data": {} }
```

`code` 与 HTTP 业务码相同。

| cmd | 方向 | data |
|-----|------|------|
| `conn.ready` | 下行 | `{ "server_time", "heartbeat_sec" }`。升级成功后的第一帧，不含消息 |
| `ping` / `pong` | 上行 / 应答 | 空对象。用 `req_id` 配对 |
| `msg.send` | 上行 | 与 HTTP 发送体相同 |
| `msg.send.ack` | 应答 | 消息对象，`seq` 是发送者自己的 |
| `msg.push` | 下行 | 消息对象，`seq` 是这条连接上的用户自己的。只推他看得到的 |
| `conv.update` | 下行 | 会话对象。自己的最后一条变化时推给自己的在线连接 |

心跳：客户端按 `heartbeat_sec`（25）发 `ping`。70 秒没有入站帧，服务端关闭连接。

## 错误码

通用码用 `modules/kit` 的 codeerror：参数 1000、未登录 1005、用户不存在 1007、无权限 1009、封禁 1014、系统 1。

| code | 何时 |
|------|------|
| 1104 | 还不是这场私聊的成员，或对端关系不存在（历史接口） |
| 1105 | 对端是自己 |
| 1106 | 内部 token 不对 |
| 1107 | 文本为空或超长；`content_type` 不是 1；`visibility` 不是 1、2、3；不可见的一侧却要求更新预览 |

`open` 和用户 `send` 在对方用户存在时会把成员行补齐，不因为「还没 open」返回 1104。历史拉一个自己没有成员行的对端，返回 1104。
