# IM 审查稿

一对一聊天的方案，供审查。这里只定范围和契约，没有实现代码。

IM 是独立服务。它和商城业务没有关系，也不读写商城的库、文件和密钥。两边只共用 `modules` 里的代码：

| 模块 | IM 用它做什么 |
|------|----------------|
| `modules/kit` | 日志、JWT、错误码、HTTP 响应、一致性哈希 |
| `modules/user` | 注册、登录、资料、封禁 |
| `modules/file` | 代码可引用。一期消息只有文本，不走上传 |

这些模块由 IM 进程自己初始化。用户表和聊天表都在 IM 的 `im.db` 里。

## 这一版定下来的点

1. **不建 `im_conversation`**。原来那张表上的字段写在 `im_conversation_member` 上，每个用户一行，各记各的。
2. **消息 id 和序号是两套数**。id 全局唯一。序号只在「这个用户看得到的消息」里从 1 连续增加，记在该用户的 `last_seq`。
3. **系统可以代替 A 发**。有三种可见性：只给 B、只给 A、A 和 B 都看见。看不见的那一侧不加视图序号。
4. **会话预览单独控制**。内部发送对 A、B 各有一个开关，决定这次写不写该侧列表上的预览。用户自己发则两侧都写。
5. **消息行有同步序号 `seq`**。新建时分配。以后这条消息被更新，`seq` 改成更大的新值，客户端按它拉增量。视图序号 `seq_low` / `seq_high` 创建后不改。
6. **用户自己发的消息双方都看见**，两侧预览都更新。
7. **正文只有文本**。`content_type` 留着，一期只接受文本。
8. **已读、未读、撤回、置顶、隐藏、拉黑本期都不做**，表和接口里不留这些字段。
9. **同步算法先维持原文**。`seq` 在更新时改写、预览开关这两点和 [同步](同步.md) 还没合到一起，明天再看。
