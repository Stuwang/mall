# 开发

两个项目共用这一套工具链。各自怎么启动见 [商城 / 开发](mall/开发.md)。IM 的启动写在 `im_web_app/README.md`。

## 依赖

- Go 1.23 及以上（当前工作区声明为 1.24.1）
- Node.js（改 `admin`、`web_app` 或 `im_web_app` 时需要）

`protoc` 和插件不需要自己安装。`go run build.go proto` 会按 `build.go` 里写死的版本下载到仓库 `bin/`，生成时只用这些文件。

在仓库根目录执行 Go 命令，这样会用到 `go.work`。

## 生成 pb

只改 proto，不要手改 `*.pb.go`、`*_http.pb.go`、`*_grpc.pb.go` 和 `server/openapi.yaml`。

```bash
go run build.go proto
```

第一次会把 `protoc` 36.2，以及 `protoc-gen-go`、`protoc-gen-go-grpc`、`protoc-gen-go-http`、`protoc-gen-openapi` 装进 `bin/`。版本写在 `build.go`。`protoc-gen-go-http` 用 Kratos v2 插件的最新提交，v3 插件会生成 `kratos/v3` 的 import。版本戳一致时下次直接复用。本机 PATH 里的 protoc 不会参与生成。

这条命令会生成：

| 源文件 | 产物 |
|--------|------|
| `server/api/**/*.proto`（路径中含 `errors` 的除外） | Go、HTTP、gRPC |
| `modules/user/api/user/user.proto` 及其引用的 `base.proto` | Go、HTTP、gRPC |
| `im/api/**/*.proto` | Go、HTTP、gRPC |
| `modules/kit/**/*.proto` | 只有 `.pb.go`（这些文件没有 HTTP/gRPC service） |
| 上述商城接口和用户接口 | `server/openapi.yaml` |

## 编译

仍在仓库根目录：

```bash
go run build.go build server      # bin/server（Windows 为 bin/server.exe）
go run build.go build allinone    # bin/allinone
go run build.go build im          # bin/im（Windows 为 bin/im.exe）
go run build.go build kit         # 也可写 user、file
go run build.go build all         # 共享模块，以及 server、allinone、im
```

`build allinone` 只编译 Go，并嵌入 `server/cmd/allinone/static` 里已经放好的前端文件。要先构建商城前端再打进二进制，用 [商城 / 部署](mall/部署.md) 里的脚本。
